# mini-agent-harness 实战复盘

学完 learn-claude-code 后，我想把 s15 整理成一个自己能继续用、继续改的项目。原来的代码把功能都串起来了，但三千多行放在一个文件里，找一个功能不难，弄清它和其他部分的关系就费点劲。所以我先顺着一次请求把代码走了一遍，理清模型、工具、记忆和任务之间的关系，再按职责拆开。过程中发现记忆还依赖 s09，就把它一起整理进来，补上依赖配置、启动入口和示例，让项目可以独立运行。

结构上，我把最核心的循环放在 `core/agent.py`，它负责调用模型、接收工具请求，再把执行结果送回去。`models/` 处理 Anthropic 和 OpenAI 的接口差异，`tools/` 放读写文件、执行命令这些具体操作，工具注册表负责把名称、参数和执行函数对应起来。模块之间先约定好参数和返回格式，再由 `app.py` 创建并连接起来；`cli.py` 接收终端输入，`config.py` 读取本地 `.env`。这样以后换模型、加工具时，改动的位置比较明确，也方便单独测试。

主流程跑通后，我再把长任务需要的功能接进去。`context/` 管技能、记忆和历史压缩：参考资料需要时再读，有用的信息留到下次，太长的输出先存到文件。`tasks/` 记录任务状态和前后依赖，`teams/` 负责队友的启动、消息和协作；需要并行改代码时，可以给任务分配独立的 worktree。`runtime/` 管后台任务和定时通知，结果出来后再交回主循环处理。`mcp/` 则负责连接真实的外部工具，发现工具后注册进同一张工具表，继续沿用现有的调用流程。

实际用起来，就是我输入一个需求，程序准备好上下文交给模型，模型提出要读文件、改代码或者运行测试，程序检查权限后执行，再把结果交回模型，直到这一轮结束。收尾时，我补了异常处理、资源清理和测试，95 项测试及四组环境的 CI 都通过了。模型部分用替身检查接口转换，MCP 则跑了真实的本地通信。整个项目做下来，最花心思的还是各部分的交接：谁保存状态，结果交给谁，出错后怎么继续。把这些关系理顺之后，代码就好读多了，后面要加功能也知道从哪里下手。
